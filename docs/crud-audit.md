# CRUD 점검 — 2026-11-01

현재 소스와 연결된 Supabase 프로젝트를 읽기 전용으로 확인했다. 이 점검은 DB 저장 기능을 새로 구현하거나 Production을 변경하지 않는다.

Supabase 호출은 인증에서만 사용하며, 프로젝트·할 일·운동·거래를 조회하거나 저장하는 `.from(...)` / RPC 호출은 없다. 따라서 화면 테스트 통과를 영구 저장 완료로 해석하면 안 된다.

## 백엔드 확인

- 대상: Supabase `daily-planner` (`pjtakegjnaciclfwlfba`). 조회 시 상태 `INACTIVE`.
- `list_tables` 응답: `Database is possibly not accessible at the moment`. 실제 테이블 상태와 CRUD는 검증 불가.
- security advisor 응답은 빈 목록이지만 DB 접근이 불가능하므로 이를 보안 검증 통과로 해석하지 않는다.
- 저장소의 초기 migration에는 24개 사용자 데이터 테이블, `user_id` 기반 RLS, authenticated CRUD 권한이 있다. 원격 적용 여부는 이번 점검에서 확인하지 못했다.

## 연결 전 해결할 소스 차이

- 앱 ID는 `task-...` 같은 문자열인데 DB ID는 UUID다. DB가 발급한 ID를 사용해야 한다.
- 할 일의 사용자 정의 구분을 저장할 DB 컬럼/테이블이 없다.
- 프로젝트 `dueDate`는 DB `end_date`, 할 일 `dueDate`는 DB `due_at`에 대응시키는 변환이 필요하다.
- 운동의 종목·세트·횟수·중량은 UI에서는 한 객체지만 DB에서는 세션·종목·세트로 나뉜다. 여러 테이블의 등록/수정을 한 트랜잭션으로 처리해야 한다.
- 거래의 분류·계좌는 UI에서 문자열, DB에서는 외래키다. 이름과 ID의 매핑이 필요하다.
- 로그아웃 후 다른 계정으로 전환해도 기존 화면의 React 데이터가 초기화되지 않는다. 실제 사용자 데이터를 연결할 때 계정 전환 시 캐시와 화면 상태를 비우고 다시 조회해야 한다.
- RLS의 행 소유자 검사는 있지만 외래키로 연결한 프로젝트·운동·계좌 등의 소유자 일치 제약은 별도 보완이 필요하다.
- DB 삭제는 연결된 데이터 처리 정책과 저장 호출이 필요하다. 기존 `deleted_at` 컬럼을 이용한 복구 가능한 삭제를 고려할 수 있다. 할 일·운동·가계부의 확인 UI와 화면 삭제는 후속 구현으로 추가했다.

## 다음 검증 순서

1. Supabase 프로젝트를 재개하고 실제 테이블·migration·RLS·권한을 확인한다.
2. 사용자 정의 구분의 서버 저장 모델과 위 매핑을 추가한다.
3. 네 가지 주요 데이터의 조회·등록·수정·삭제와 오류·로딩 상태를 연결한다.
4. 두 테스트 계정으로 서로의 데이터가 보이거나 변경되지 않는지 확인한다.
5. 등록 → 새로고침 → 수정 → 재로그인 → 삭제 → 새로고침을 실제 Preview와 DB에서 대조한다.

## 이번 변경의 확인 범위

회사·개인은 기본 구분이며, 그 외 구분은 직접 추가한다. 추가한 구분은 필터·등록·수정·상세·카드 표시에서 동일하게 사용한다. 기존 `church` 구분은 성당으로 표시한다. 회사 이외 구분에서는 프로젝트 입력칸을 숨긴다. 추가 구분만 브라우저에 유지되며, 할 일 등 기존 데이터의 저장 방식은 바꾸지 않았다.

- 자동 테스트 28개, ESLint, TypeScript 검사, 프로덕션 빌드 통과.
- 실제 로컬 브라우저에서 성당 구분 추가 → 선택 → 할 일 등록 → 필터 표시 확인. 새로고침·데모 재로그인 후 추가 구분 유지 확인. 브라우저 오류 로그 없음.

## 후속 구현: 할 일·운동·가계부 삭제

세 가지 상세 팝업에서 삭제 → 대상 확인 → 삭제하기 순서로 제거한다. 취소·ESC·뒤로가기는 항목을 지우지 않는다. 삭제 후 할 일의 주·월·칸반 및 홈 목록, 운동 목록, 가계부 건수·잔액·지출 합계가 갱신된다. 삭제 대상 버튼이 사라지면 키보드 포커스는 화면 제목으로 이동한다.

현재 삭제는 기존 React 상태에 적용한다. DB 영구 삭제 호출은 여전히 미연결이며 새로고침하면 샘플 데이터가 복원된다. 새 삭제 회귀 테스트를 포함해 자동 테스트 총 34개가 통과했다.
